# Idle parking holds (park-hold) Implementation Plan

**Goal:** keep an idle parent attached while a direct child remains attached or a family notice awaits delivery, and expose a persisted operator “do not park” pin. Implement the operator decisions of 2026-10-20 in ACP core §4.7 and delegation §5.1 without a UI change.

**Architecture:** the collector derives one effective boolean from owner-scoped family lifecycle, undelivered notices and the persisted pin. Migration 22 invalidates it transactionally. The coordinated Store guard flushes committed invalidations before releasing its owner gate; delegated handoff explicitly flushes first. Capability-gated host state survives pre-attachment updates and reconnect. The serialized actor suppresses only automatic parking and restarts its clock once on release.

**Tech stack:** existing Rust, SQLite, tokio, axum and generated TypeScript/JSON Schema. No dependency or adapter pin changes. Base: `b641f40f7f97955f9b6601b678d3d6ecfb7fcc35`; built implementation: `6409b39cb8dbb885efd895cfb8de83103a23069b`. Plan 3c supplies this structure; exact code in the patches wins over prose.

## Decisions this plan makes where the spec is silent

These are **designer's recommendations**, awaiting independent parent review.

| Detail | Choice and reason |
|---|---|
| Where the hold lives | Collector computes family state; host retains and applies only the effective boolean. No same-host assumption. |
| Direct child | Count lifecycle outside parked/closed/failed/deleted, even between turns or after routing detach/close intent. Detach is not process completion. This follows the operator's literal lifecycle rule. |
| Notice states | parent_queued, waiting_config and awaiting_reconciliation retain a hold; factual parent_delivered, operator fallback, resolved and obsolete do not. Socket handoff is not delivery. |
| Publication | A Store guard flushes committed dirty rows under the existing owner gate, without a Store→Hub→Store cycle. Weak Hub ownership prevents a reference cycle. Explicit pre-handoff flush covers parked-child resume; failures use existing handoff compensation. Recovery worker handles external/kernel invalidations or flush errors. |
| Bounds | Dirty work drains in 128-row pages, including offline/unsupported rows, until clear. Reconnect restores every current session, including false, rather than only one page. |
| Operator API | GET/PATCH /api/sessions/{id}/idle-hold. Strict SetIdlePinRequest and IdleHoldState are generated. Cookie + Origin required under the existing operator layer; no step-up for a reversible resource preference that changes no credential/grant/execution policy (kernel §3.4). |
| Persistence and skew | Pins survive park/close/restart. No frame reaches a host lacking idle_hold. Old hosts retain prior reaping/durable-report fallback. New hosts retain holds across disconnect; a newly changed offline pin waits for reconnect. A downgraded old collector cannot clear a retained new-collector hold. |

+fn received_hold(rx: &mut tokio::sync::mpsc::UnboundedReceiver<CollectorFrame>, id: &str) -> Option<bool> {
+    let mut held = None;
+    while let Ok(frame) = rx.try_recv() {
+        if let CollectorFrame::SetIdleHold {
+            session_id,
+            held: value,
+        } = frame
+            && session_id == id
+        {
+            held = Some(value);
+        }
+    }
+    held

## Decisions

The approved design selects an address-only `Hennery-Client-IP`, at most eight
exact peers and a strict single bare IP. Standard forwarding and identity headers
are ignored. Trusting loopback also trusts local processes for abuse accounting;
backend access and edge caps remain deployment obligations.

Implementation details covered by the maintainer-delegated review; the request-cap amendment awaits scoped re-confirmation:

| Choice | Alternative and reason | Risk to review |
|---|---|---|
| Canonicalize mapped IPv4 in both peer allowlist and effective address; refuse duplicate canonical peers and unspecified/multicast peers | Silently accepting ambiguous/redundant entries hides configuration mistakes | Exact-peer meaning and canonicalization parity |
| One outer collector layer resolves before Origin/session/body work; handlers reuse the inserted address | Re-parsing in each limiter could drift, including on success | Layer ordering and standalone extractor fallback |
| Standalone test routers retain an unconfigured peer fallback | Requiring a global extension breaks existing embedded/test consumers | Missing metadata returns fixed 500, never an invented peer |
| Missing dedicated header uses the TCP peer and is identified in doctor | Rejecting every missing field breaks local `up` enrollment | Health/configuration do not prove attribution |
| Explicit fixture certificates, ACME off, no proxy response caching/logging/retries | Contacting public CA services in tests is outside isolated verification | Certificate reload, nonce/Origin and streaming preservation |
| nginx supplies edge caps; Caddy core requires separately tested firewall/ingress caps | Claiming Caddy's backend limiter bounds unauthenticated TLS/socket floods would be false | Public gate stays open until deployment caps and live adapters/MCP are recorded |
| HTTPS README origin/port/code are explicitly marked placeholders; only those can change | Replacing an unmarked scheme/host could make unsupported instructions appear green | Literal whitelist, placeholder guard and actual shell execution |

+    pub fn is_configured(&self) -> bool {

+    pub fn resolve(&self, peer: IpAddr, headers: &HeaderMap) -> Result<ClientAddress, InvalidClientAddress> {
+        let peer = canonical(peer);
+        let mut address = ClientAddress {
+            peer,
+            effective: peer,
+            source: Source::Peer,
+        };
+        if !self.peers.contains(&peer) {
+            return Ok(address);
+        }
+        let mut values = headers.get_all(HEADER).iter();
+        let Some(value) = values.next() else {
+            address.source = Source::MissingHeader;
+            return Ok(address);
+        };
+        if values.next().is_some() {
+            return Err(InvalidClientAddress);
+        }
+        let ip = canonical(
+            value
+                .to_str()
+                .map_err(|_| InvalidClientAddress)?
+                .parse::<IpAddr>()
+                .map_err(|_| InvalidClientAddress)?,
+        );
+        if !valid(ip) {
+            return Err(InvalidClientAddress);
+        }
+        address.effective = ip;
+        address.source = Source::Proxy;
+        Ok(address)
+    }

+fn command(root: &Path) -> Command {
+    let mut cmd = Command::new(env!("CARGO_BIN_EXE_hennery"));
+    for (key, _) in std::env::vars_os() {
+        if key.to_string_lossy().starts_with("HENNERY_") {
+            cmd.env_remove(key);
+        }
+    }
+    cmd.env("HOME", root.join("home"))
+        .env("XDG_DATA_HOME", root.join("data"))
+        .env("XDG_CONFIG_HOME", root.join("config"))
+        .env("XDG_STATE_HOME", root.join("state"))
+        .env("XDG_CACHE_HOME", root.join("cache"))
+        .env_remove("SSL_CERT_FILE")
+        .env_remove("SSL_CERT_DIR")
+        .stdin(Stdio::null());
+    cmd
+}

+# Same-machine HTTPS/WSS deployment
+
+Use one TLS origin and one collector, with the plaintext backend on loopback.
+A plaintext LAN hop is outside this recipe. The templates route enrollment,
+health/readiness, WebSockets, browser/SSE and MCP through the same origin.
+They preserve Host, Origin and the 101 nonce; they neither synthesize browser
+identity nor retry enrollment. No response cache, access/body logging or
+stream compression is enabled. nginx disables request/response buffering;
+Caddy flushes immediately and lets streams survive a reload for five minutes.
+The collector still enforces each route's body limits and 32 MiB WSS messages.
+
+Choose [Caddyfile](Caddyfile) or [nginx.conf](nginx.conf). These exact files
+are executed by `hennery-testkit/tests/reverse_proxy.rs` and the CLI deployment
+and README tests, using disposable CA/leaf certificates and loopback ports.
+All replacements are explicit placeholders, never changes to security rules:
+
+| Placeholder | Deployment value |
+|---|---|
+| `@TLS_PORT@` | Your HTTPS listener port, normally 443 |
+| `@BIND_V4@`, `@BIND_V6@` | Frontend listener addresses, normally 0.0.0.0 and ::; the backend remains loopback |
+| `@BACKEND_PORT@` | Collector loopback port, normally 7117 |
+| `@CERT@`, `@KEY@` | Absolute certificate-chain and private-key paths, readable by the proxy; protect the key |
+| `@ROOT@` | nginx's writable private runtime directory, for PID/log/temp files |
+| `@ADMIN_PORT@` | Caddy's loopback-only admin port; do not expose it |
+
+Supply certificates for the actual public DNS name through your deployment's
+certificate management. This Caddy template uses explicit PEM files and turns
+ACME off; the test does not contact certificate services. Renew the leaf under
+the same CA, then reload: `caddy reload --force --config <rendered-Caddyfile>`
+(with its configured local admin address) or send SIGHUP to your nginx master.
+The fixture runs the reload operation and reconnects over the same trust.
+
+Before setup, use the README's `up-public` block with your public HTTPS origin.
+Already set up? Use the existing admin public-URL reset: changing the flag alone
+does not replace the stored browser origin and passkey identity. Remote hosts
+use the README's `join-public` block and saved WSS endpoint. An SSH tunnel is an
